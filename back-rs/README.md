# back-rs

Rust-версия `back/`. Делает то же, что Go-версия:
- докачивает свечи Bybit в ClickHouse;
- перебирает стратегии «индикатор × индикатор × TP/SL»;
- отдаёт фронту `POST /api/get_quotes` (protobuf из `core/api/quotes.proto`).

## Запуск

Конфиги те же, что у Go: `config.yaml` и `config_{PAIR}.yaml`. Каталог с ними задаётся `CONFIG_DIR`, по умолчанию текущий.

```bash
CONFIG_DIR=../back/src cargo run --release
```

ClickHouse подключается только по HTTP-порту (8123). Нативный порт 9000 не поддерживается.

## Проверки

```bash
cargo test --release                 # unit-тесты и сверка с Go по фикстурам
cargo bench                          # prepare и полный перебор на синтетике (criterion)
```

Golden-фикстуры генерирует Go-тест, их нет в git. Команду нужно запускать из `back/src`:

```bash
GOLDEN_OUT=$PWD/../../back-rs/tests/fixtures/golden.json go test ./analyzer -run TestGolden
```

Синк в живой ClickHouse пишет во временную таблицу и сравнивает результат с основной:

```bash
CONFIG_DIR=../back/src cargo test --release --test clickhouse -- --ignored --nocapture
```

Сравнение API двух запущенных серверов:

```bash
cargo run --release --example api_parity -- http://localhost:8890 http://localhost:8891
```

## Чем отличается от Go

**Перебор.** Результаты те же, работает быстрее:
- идёт по сделкам через таблицу «следующий сигнал», а не по всем сигналам;
- сигналы пар не хранятся;
- пары обрабатываются блоками на одном TP/SL.

Взвешенный коэффициент считается как `exp(Σ w·ln c)` вместо `Π c^w`. Поэтому `weighted pr/dd` отличается от Go на ~1e-15 относительно. Решения фильтров и остальные метрики совпадают бит в бит, это проверяет `tests/golden.rs`.

**Индикаторы.** Go на arm64 сливает `a*b + c` в FMA, Rust так не делает. Поэтому значения индикаторов отличаются на ≤3e-15. Как следствие, у Go появляются «сигналы» между математически равными индикаторами, например `tema(1.0)` и `dema(1.0)` на одном источнике. На урезанной сетке SOLUSDT это 12 лишних пар у Go. Лучшая стратегия от этого не меняется.

**Порядок вывода.** Обход детерминированный, в Go он зависел от случайного порядка карт. Промежуточные «новые максимумы» могут идти в другом порядке, итоговый лучший результат тот же.

**Остановка.** Ctrl+C или SIGTERM останавливают и HTTP-сервер, и перебор. Go дожидался конца перебора.

**Устойчивость к входным данным.** То, на чём Go падал, теперь обрабатывается:
- SMA с окном < 1 или длиннее истории даёт результат, а не панику;
- запрос без `ind1` или `ind2` использует значения по умолчанию.

**Таймфреймы.** Для `1d` в Bybit уходит интервал `D` (Go отправлял недопустимый `1440`). `1w` не поддерживается: такого значения нет в Enum8 колонки `timeframe`.

**Логи.** JSON с суточной ротацией, хранится `log.days` файлов. Параметр `log.size` игнорируется, потому что ротации по размеру в tracing-appender нет.
